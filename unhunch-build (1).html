Prompt 01: Foundation

ScaffoldPWAlocalStorageTailwind
prompt_01.txt

I'm building "Unhunch," a mobile-first web app for desk workers with rounded shoulders and upper-back/neck pain. It generates short mobility routines matched to the user's equipment, mobility constraints, and time, and tracks pain, sessions, and daily streaks with a playful spine mascot. We will build it step by step across multiple prompts — do NOT build everything now. In this prompt, only set up the foundation.

Tech stack: React + Vite frontend with Tailwind CSS, Express (Node) backend in the same Repl. In production, Express serves the built client. No database — all user data lives in browser localStorage for now. Add a PWA manifest and icons so it can install to a phone home screen. Mobile-first: design for ~390px wide screens, large touch targets (44px+).

•

Build now:

•

Project scaffold with client and server folders, dev + production scripts.

•

A versioned localStorage wrapper module at client/src/lib/storage.ts with get/set helpers and a schemaVersion field (start at 1) plus a migrate() stub.

•

An app shell with bottom tab navigation: Home, History, Settings (placeholder screens are fine).

•

A simple warm, friendly visual theme: soft cream/off-white background, one coral accent color, rounded cards, sans-serif. No content yet beyond placeholders.

Do not build onboarding, exercises, or any API calls yet. Confirm the app runs and installs as a PWA before we continue.

Prompt 02: Onboarding Wizard

4-step wizardProfileAccessibilitylocalStorage
prompt_02.txt

Now build the first-run onboarding wizard. It should appear automatically when no profile exists in localStorage, and be re-editable later from Settings ("Edit profile"). Four steps, one screen each, big thumb-friendly controls, progress dots at the top.

Step 1 — Goals & symptoms: multi-select chips: rounded shoulders, neck pain, shoulder pain, upper-back stiffness, low-back ache, just prevention. For each pain-related selection, show an optional 0–10 slider labeled "How much does it bother you today?" — these seed the pain-tracking baseline.

Step 2 — Equipment: multi-select with simple icons: None/bodyweight only, Wall, Desk & chair (pre-checked, cannot uncheck), Resistance bands (with light/medium/heavy sub-select), Pull-up bar, Doorway, Foam roller, Light dumbbells.

Step 3 — Mobility & constraints: (a) Position capabilities multi-select: can stand, can walk, can get down to and up from the floor, seated only / wheelchair user. Selecting "seated only" auto-deselects the others. (b) "Areas to avoid loading" chips: wrists, elbows, left shoulder, right shoulder, neck, lower back, hips, knees, ankles. (c) A free-text field: "Anything else we should know? (injuries, surgeries, pregnancy...)". (d) A prominent "None of these apply — skip" button.

Step 4 — Time: session length choice: 5, 10, 15, or 20 minutes, with 5 minutes visually promoted as "Great for building a daily habit." Frame the commitment as "a few minutes every day."

Save the whole profile to localStorage using the storage module. After finishing, land on Home. Include a short disclaimer on the final step.

SessionExercisesTimerSkip
prompt_03.txt

Build the session player using static routines for now (the AI generator comes later).

Create client/src/data/fallbackRoutines.ts containing 4 hand-written routines, each an ordered list of 5–7 exercises. One routine per profile type: (1) seated-only, (2) wall + desk only, (3) bands available, (4) pull-up bar available. Every exercise object: { id, name, targetArea, position: "seated"|"standing"|"floor"|"wall", equipment, durationSeconds OR reps, instructions (2–4 plain sentences), whyThisHelps (1 sentence), modification (string or null) }.

Choose gentle, safe, well-known posture exercises (wall angels, band pull-aparts, doorway pec stretch, chin tucks, seated thoracic rotations, dead hangs only for the pull-up bar routine). Seated-only routine must contain zero standing or floor exercises.

A "Start today's session" button on Home picks the best-matching routine for the stored profile. Session player: full-screen, one exercise at a time. Show name, position badge, instructions, "why this helps." Timed exercises get a large countdown with a gentle chime; rep exercises get a "Done" button. Big Next/Back buttons. Include a "Can't do this one" button that asks why (Pain / No equipment / Unclear) and skips forward, logging the skip.

Session end screen: for each area in the user's painBaseline, a 0–10 slider; a 1–5 difficulty rating; a Finish button. Save to localStorage.

Prompt 04: Progress & Pain Tracking

RechartsSparklinesHistoryInsights
prompt_04.txt

Build progress and pain tracking on Home and History.

Home: under the start button, show a small 30-day sparkline for each tracked pain area with a plain-language trend label: "improving" (30-day average clearly falling), "steady," or "worse this week" (7-day average above 30-day average). Use Recharts.

History screen: (1) a monthly calendar view where each day with a completed session gets a filled dot; (2) a list of past sessions (date, duration, completed/partial, difficulty); (3) a simple honest insights card computed with plain rules, e.g. "9 sessions this month. Neck pain average: 5.1 → 3.8." Never phrase insights as medical claims — correlations only.

If a tracked pain area has averaged 7 or higher for the last 14 days, show a gentle non-alarming banner suggesting they check in with a healthcare professional.

Prompt 05: Daily Streaks

StreaksStreak freezeCalendarConfetti
prompt_05.txt

Build daily streaks. A streak is consecutive calendar days with at least one completed session — even a 5-minute one counts. Compute streaks in a dedicated module client/src/lib/streaks.ts with unit-testable pure functions (input: array of session dates; output: current streak, best streak).

Rules: (1) One automatic "streak freeze" per calendar month: the first missed day each month is silently forgiven and the streak continues; show a small "freeze used" marker on that calendar day. (2) A second missed day breaks the streak. Store { current, best, freezeUsedThisMonth } and recompute on app load and session completion.

UI: a streak widget on Home showing current streak with a flame or bone icon, best streak, and freeze status ("1 freeze available this month"). On the History calendar, streak days form a visually connected run. When a session completion extends the streak, celebrate briefly (confetti burst) — respect prefers-reduced-motion by swapping animation for a static congratulations.

Prompt 07: Spine Mascot — Sunny

SVGAnimationCSS transitionsMascot
prompt_07.txt

Build the session mascot: a friendly cartoon spine with a smiley skull, rendered as one inline SVG component (client/src/components/SpineMascot.tsx). No animation libraries — SVG + CSS transitions only.

The mascot has a skull with a face and a stack of vertebrae (one vertebra per exercise in the current routine, minimum 5). States: (1) "slumped" — vertebrae offset in a C-curve, sleepy half-closed eyes, flat mouth; (2) intermediate — as each exercise completes, the next vertebra animates into vertical alignment with a small springy snap and the face gets progressively happier; (3) "aligned" — perfectly stacked spine, big smile, rosy cheeks, two sparkle shapes. Skipped exercises still align their vertebra, just without the sparkle flourish.

Show the mascot: small on Home (reflecting whether today's session is done), and prominently in the session player above the exercise card, updating live as exercises complete. All state changes must be instant (no motion) when prefers-reduced-motion is set. The mascot must render identically for all users — its framing is "aligned and strong," never "stand up straight."

Prompt 09: Rules-Based Routine Generator

Exercise libraryClient-sidePure functionsUnit tests
prompt_09.txt

Replace the static routine selection with a rules-based routine generator — no AI, no API, no backend needed. If the Express server exists only for API proxying, remove it and make this a fully client-side app.

1. Create client/src/data/exerciseLibrary.ts: a library of 35-40 safe, well-known posture and mobility exercises, each tagged: { id, name, targetArea: "upper_back"|"neck"|"chest"|"shoulders"|"core"|"hips", position: "seated"|"standing"|"floor"|"wall", equipment: "none"|"wall"|"desk_chair"|"bands"|"pullup_bar"|"doorway"|"foam_roller"|"dumbbells", loadsAreas: string[] (which body areas this exercise stresses, using the same area names as the profile's avoidAreas), intensity: "gentle"|"moderate", durationSeconds or reps, instructions (2-4 plain sentences), whyThisHelps, modification (string or null) }. Include plenty of seated and wall options so every profile type gets real variety. Choose conservative, widely recommended exercises only (chin tucks, wall angels, band pull-aparts, doorway pec stretch, thoracic rotations, scapular squeezes, etc.) — nothing ballistic or end-range loaded.

2. Create client/src/lib/generateRoutine.ts with a pure function generateRoutine(profile, painTrend, recentSkips, seed): - Filter the library hard: only equipment the user has; if seatedOnly, position must be "seated"; if canFloor is false, no "floor"; if canStand is false, no "standing"; exclude any exercise whose loadsAreas overlaps the profile's avoidAreas; exclude exercises the user has skipped 3+ times for pain. - From the filtered pool, build a session that fits sessionMinutes: start with 1-2 gentle mobility exercises, cover at least 3 different targetAreas weighted toward the user's stated goals, and end with one gentle exercise. If painTrend is rising for an area, use only "gentle" intensity exercises for that area. - Use the seed (date-based) so each day's routine differs from yesterday's, and a "Shuffle" button passes a random seed for a new combination. Never repeat the exact same routine two days in a row when the pool allows. - If the filtered pool is too small for the time budget, use fewer exercises rather than violating any constraint, and never return an empty routine — the gentlest seated exercises are always available as a floor.

3. Wire it in: Home generates today's routine from the profile on load, Shuffle regenerates, the session player consumes it unchanged. Add unit tests for the filter logic: a seatedOnly profile must never receive a standing or floor exercise, and avoidAreas must never be loaded.

Final accessibility and polish pass across the whole app:

Audit all touch targets to 44px minimum; session player fully operable one-handed with thumb-reachable controls.

•

Timers: visual countdown + chime + vibration via navigator.vibrate where supported.

•

prefers-reduced-motion respected globally — verify mascot, skeleton, confetti, and screen transitions all degrade to instant state changes.

•

Color contrast: all text at least WCAG AA against backgrounds.

•

Empty states: friendly guidance on Home before the first session, on History with no data, and a graceful screen when the API and fallbacks both fail.

•

PWA check: correct icons, theme color, offline shell loads with cached routine, add-to-home-screen works on iOS Safari and Android Chrome.

•

Copy pass: warm, encouraging, plain language everywhere; no guilt-based messaging (missed days say "welcome back," never "you broke your streak"); pain-related copy is always neutral and supportive.
