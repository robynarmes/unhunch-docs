🦴 Software Specification

Unhunch.

A mobile-first web app for desk workers with rounded shoulders, tight chests, and upper-back/neck pain. Built on Replit. Fully client-side — local-first data, rules-based routine generation, no backend required.

React + Vite Client-side only localStorage PWA Tailwind CSS
01

Summary

Corporate desk workers spend 8+ hours a day in flexed, shoulders-forward postures. The result is a predictable cluster: rounded upper back (thoracic kyphosis), forward head, tight pecs and hip flexors, weak mid-back, and nagging shoulder/neck pain.

Unhunch generates short, personalized mobility and strengthening routines that fit the user's real constraints:

●

Equipment they actually have (a doorframe pull-up bar, a resistance band in a drawer, or nothing but a wall)

●

Their body and mobility situation (wheelchair users, standing-limited users, existing injuries, pain areas to avoid loading)

●

Their schedule (5-minute desk breaks vs. a 20-minute evening session)

The app tracks completed sessions, self-reported pain over time, and streaks — turning posture work from a vague intention into a visible habit with feedback.

V1 Principles

●

No login. All data lives in the browser (localStorage), with export/import so nothing is lost. Accounts and sync are a later phase.

●

Rules-based routines. A curated exercise library filtered by the user's equipment, mobility constraints, and pain trends — purely client-side, no API key or backend required.

●

Not a medical product. Clear disclaimers, conservative exercise selection, and "stop if sharp pain" guidance baked into every routine.

03

Feature Breakdown

3.1

Onboarding & Profile

A 4-step wizard, each step one screen, thumb-reachable controls:

Step 1Goals & Symptoms

Multi-select chips: rounded shoulders, neck pain, shoulder pain, upper-back stiffness, low-back ache, "just prevention." Optional pain rating (0–10) per selection — seeds the pain-tracking baseline.

Step 2Equipment

Multi-select with icons: None/bodyweight, Wall, Desk & chair (pre-checked), Resistance bands (light/medium/heavy sub-select), Pull-up bar, Doorway, Foam roller, Light dumbbells.

Step 3Mobility & Constraints

Position capabilities, areas to avoid loading (body map/chips), free-text constraint field, and a "None of these apply" fast path.

Step 4Time

Session length: 5/10/15/20 min. 5-minute option visually promoted as "Great for building a daily habit."

3.2

Rules-Based Routine Generation

1

Exercise library (exerciseLibrary.ts): 35–40 curated posture exercises, each tagged with targetArea, position, equipment, loadsAreas, and intensity — conservative and widely recommended only.

2

Hard filter: only equipment the user has; seated-only profiles get only seated exercises; avoidAreas exercises are excluded; exercises skipped 3+ times for pain are dropped.

3

Session builder (generateRoutine.ts): selects exercises to fit sessionMinutes, covers ≥3 targetAreas weighted toward stated goals, starts and ends gently. If a pain area is trending up, uses only "gentle" intensity for that area.

4

Daily variety: a date-based seed ensures each day's routine differs from yesterday's. "Shuffle" passes a random seed for a fresh combination.

5

Client caches the routine in localStorage. If the filtered pool is too small, the generator uses fewer exercises rather than violating any constraint — it never returns empty.

Fully Client-Side

No API key, no backend, no network request required for routine generation. The app works entirely offline after the initial page load.

3.3

Session Player

●

Full-screen, one exercise at a time. Big text, big Next/Back buttons, optional per-exercise countdown timer with a gentle chime.

●

Each screen shows: name, position icon, instructions, "why this helps," and a "Can't do this one" button → logs the skip reason (pain / equipment / unclear) and advances.

●

Skip reasons feed future generations ("user repeatedly skips floor work → stop offering it").

●

Session end screen: quick pain check-in (0–10 sliders), one-tap mood/difficulty rating, confetti on streak milestones.

3.4

Progress & Pain Tracking

●

Pain log: every check-in stores {date, area, score}. Home screen shows a 30-day sparkline per tracked area with a trend label ("improving," "flat," "worse this week").

●

Session log: date, routine ID, completed/partial, skipped exercises, difficulty rating.

●

Insights (rule-based): "You've completed 9 sessions this month. Your neck pain average dropped from 5.1 → 3.8." Correlations, not medical claims.

3.5

Streaks

●

Streak = consecutive calendar days with at least one completed session (even a 5-minute one).

●

Show current streak, best streak, and a monthly calendar heat map.

●

One "streak freeze" per month (auto-applied) — so a single missed day doesn't wipe out weeks of momentum.

●

Pair daily streaks with the 5-minute session as the promoted default: the ask is "do something every day," not "do a full workout every day."

3.6

Visual Identity & Delight — "Sunny the Spine" 🦴

The app should feel playful, not clinical. Core mechanic: a friendly skeleton/spine mascot that physically improves as you do.

Session Progress

A cartoon spine with a smiley skull starts slumped. Each completed exercise snaps one vertebra into alignment with a satisfying animation + haptic tick. Finish → fully upright spine, big smile, tiny celebration.

Streak Progress

A full skeleton assembled bone-by-bone across the streak calendar — day 1 earns the skull, then vertebrae, ribs, arms, legs. 30-day streak = complete happy skeleton in a victory pose. Miss a day and the newest bone pops off — visible but recoverable, never a full reset.

Personality

Slumps and looks sleepy after missed days, stretches when you start, winces sympathetically if you log high pain (never guilt-trips). Playful about habits, never about pain or ability.

Implementation

Inline SVG with layered bone groups toggled/animated via CSS classes — no canvas or animation library needed for V1. prefers-reduced-motion swaps animations for instant state changes.

3.7

Reminders (V1-optional)

Web push is unreliable on iOS PWAs; V1 ships with an in-app "next session due" banner and an "Add to calendar" (.ics download) button. Real push notifications land in Phase 2.

3.8

Data Portability

Settings → Export data (single JSON: profile + logs) and Import data. Bridge to future accounts and safety net for localStorage clears.

Why no backend?

Routine generation is pure logic over a local exercise library — no AI API needed. The whole app ships as a static PWA and runs completely offline after first load.

05

Accessibility & Safety Requirements

●

Seated-only mode is absolute: every generated exercise must have position: seated. Enforced in code, not just in the prompt.

●

Touch targets ≥ 44px; session player operable one-handed; timer has visual + audio + vibration cues.

●

Respect prefers-reduced-motion; confetti and animations degrade gracefully.

●

Semantic HTML + ARIA labels on sliders and the body-area selector; test with VoiceOver/TalkBack.

●

Disclaimer shown at onboarding and in Settings: informational only, not medical advice. App explicitly suggests seeing a clinician if a tracked pain area stays ≥7/10 for two weeks.

06

Build Phases

Phase 1 — MVP (ship this)

Onboarding wizard → routine generation with validation + static fallback → session player → pain check-ins → cadence-based streaks → export/import. PWA manifest.

Phase 2

Accounts + sync (import local JSON on first login), push/email reminders, skip-reason-driven personalization, exercise illustrations or short looping demos.

Phase 3

Progress photos (posture side-view comparison), desk-break micro-sessions (90-second timer-triggered resets), shareable streak cards.
